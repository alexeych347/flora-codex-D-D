## 1. Поиск подсвечивает только первое совпадение

**Файл:** `client/src/components/SearchBar.tsx:61-74` (`highlight`)

Один и тот же `/gi`-regex используется и для `split`, и потом для `.test()` в
цикле по частям. У глобального regex `.test()` двигает `lastIndex`, поэтому
второе и последующие совпадения в одном названии тест не проходят и остаются
неподсвеченными.

Запрос «ра» по названию «Трава-мурава»: `split` даёт
`['Т','ра','ва-му','ра','ва']`, первая «ра» подсвечивается и ставит
`lastIndex = 2`, ко второй «ра» индекс уже за концом строки — тест ложен,
подсветки нет.

Чинится одной строкой: для проверки использовать regex без флага `g`.

**Важно:** баг существовал до ветки, в её диффе его нет. Поэтому правка пойдёт
отдельным коммитом, а не под видом мобильной адаптации.

## 2. Панель мастера подписывает редкость только цветом

**Файл:** `client/src/components/DMPanel.tsx:277-279`

Перед названием травы стоит ромб 10×13, залитый `RARITY_COLORS[rarity]`, без
подписи. Это ровно то кодирование одним цветом, против которого сформулировано
правило **The Named-Rarity Rule** в DESIGN.md: две из четырёх ступеней
(`r-rare` #3A5F8A и `r-veryrare` #7B3FA0) при дейтеранопии сходятся до
отношения светлот 1.04:1 и становятся неразличимы.

Панель мастерская, пользователь у неё один, поэтому приоритет низкий. Но
правило уже записано как общее, и ромб ему противоречит. Варианты: заменить на
`HeraldicBadge` с подписью, добавить `title`, или явно вывести панель
из-под правила отдельной строкой в DESIGN.md.

## 3. Два источника правды в мобильной пагинации

**Файлы:** `client/src/hooks/useBook.ts:21-22` и `client/src/components/Book.tsx:90-91`

`useBook` считает `totalMobilePages` и `mobilePageIndex`, но наружу их не
отдаёт. `Book.tsx` в `spreadLabel` повторяет те же два выражения дословно:

```ts
const totalMobilePages = 1 + totalSpreads * 2;
const mobileIdx = currentSpread === 0 ? 0 : (currentSpread - 1) * 2 + (mobileSide === 'left' ? 1 : 2);
```

Любое изменение модели листания (например, если обложка когда-нибудь станет
двумя страницами на мобильном — см. The Mobile-Cover Exception) придётся
вносить в двух местах, иначе счётчик молча разойдётся с навигацией.

Чинится возвратом двух значений из `useBook`.

**Там же:** порог свайпа 60px продублирован — `Book.tsx:81` и
`HerbDetailModal.tsx:146`, вместе с телом обработчика `handlePanEnd`.

## 4. `usePagedFlow` не сбрасывает страницу при смене контента

**Файл:** `client/src/hooks/usePagedFlow.ts:131, 200`

Хук принимает `contentKey`, чтобы перемерить поток при смене содержимого, но
не сбрасывает ни `page`, ни `ready`. Если контент сменится, пока хук
смонтирован, старая разбивка останется видимой при `opacity: 1` на всё время
ожидания шрифтов и анимации, а `measure` затем возьмёт `was =
offsetsRef.current[pageRef.current]` от **предыдущего** документа и откроет
новый на той странице, которая окажется рядом по вертикали.

Сейчас недостижимо: окно травы размонтируется при закрытии, и `herb.id` при
смонтированном хуке не меняется. Но параметр существует ровно для этого случая
и для него работает неверно — либо чинить (`setPage(0)`, `setReady(false)` при
смене ключа), либо убрать параметр, раз сценария нет.
